# 05-00-IO

本文件定义跨模块工件的**规范性**磁盘 I/O 契约。
本文件全部规则均为 MUST 级约束。
非规范性的目录样例移到 `./standards/en/05-io/05-01-IO_LAYOUT.md`。

## 1) 适用范围（MUST）
MUST:
- 本文件只定义磁盘 I/O 契约。
- 物理语义由 `03-00/03-01/04-00/04-01/04-02/04-03` 定义。
- 运行时数值与输入闸门继承
  `./standards/en/06-utils/06-00-RUNTIME_NUMERICS.md`。

Code form:
```text
io_contract_scope = {paths, filenames, metadata, key, read-first policy}
```

Validation:
- 任何违反本契约的工件都不得被下游复用。

## 2) 根目录与阶段锚点（MUST）
MUST:
- core 工件和全局索引文件必须位于 `paths.output_root` 下。
  run-scoped 工件必须位于解析后的运行锚点下。
- 运行输入字段 `paths.output_root` 为必填，且在本标准版本中必须严格为
  `./outputs`（不允许替代输出根目录）。
- 运行输入字段 `paths.output_run` 可选。省略时，运行锚点为
  `<output_root>/<run_name>`；设置时，`paths.output_run` 是基目录，
  运行锚点为 `<output_run>/<run_name>`。
- `L0` 磁盘锚点为 `./outputs/core/L0/`。
- `LMSM/LSJM` 磁盘锚点位于 `./outputs/core/...` 下。
- `L1/F` 对所有 scheme 和 Kramers route（RS/ED、stevens/manual）都在
  `<output_run>/L1/F` 下按 run-scoped 方式存放；RS 和 ED 共享同一套
  L1 磁盘布局。
- `L1/P`（FOPT ligand-transition vertices）和 `ligand` 是 run-scoped，
  位于 `<output_run>/L1/P/...` 和
  `<output_run>/ligand/{soc,nsoc}/n-{N}`。
- 当 `model.scheme = "ED"` 时，`IONED` 位于 `<output_run>/...`。
- material/runtime 阶段 `L2/L3` 位于 `<output_run>/...`。

Code form:
```text
root_outputs = ./outputs
anchor_L0    = ./outputs/core/L0
anchor_core  = ./outputs/core
anchor_base  = paths.output_run or paths.output_root
anchor_run   = <anchor_base>/<run_name>
```

Validation:
- core 输出位于 `paths.output_root` 之外，或 run-scoped 输出位于解析后的
  run anchor 之外，均属于契约失败。

## 3) 路径参数契约（MUST）
MUST:
- Core LMSM/LSJM 路径必须包含：
  `n-{n}_r42-{r42}_r62-{r62}_scheme-{scheme}`。
- ED 仍将参考 LMSM/LSJM 存在 `scheme-RS` 下；ED 选择由 run-scoped
  `IONED` 和 `L1/F` 工件表示。
- 路径/key 中的 ratio token `r42/r62` 是运行输入派生值：
  `r42 = F4/F2`、`r62 = F6/F2`（要求 `F2 != 0`）。
- 相邻扇区 `f^(n-1)` / `f^(n+1)` 可以使用自己的 Slater ratio（例如相邻
  元素 preset），并可不同于主扇区；每个扇区的 LMSM/LSJM 由自己的
  `(n, r42, r62)` content-addressed。由于 `L1/F` 是 run-scoped（见 §2），
  不需要额外的 `core/` 分支路径 token 来区分相邻扇区 ratio 不同的运行。
- L2 直接位于 `<output_run>/L2`。
- IONED 扇区工件位于 `<output_run>/IONED/n-{n}`。
- `L1/F` 直接位于 `<output_run>/L1/F`。
- SOPT L3 和 FOPT L3 直接位于 `<output_run>/L3`。
- 分母参数和主扇区 reference mode 是 run-scoped 输入；不得为 SOPT L3
  额外添加最终路径 token。
- L2 路径必须包含 `run_name`，且不要求 `U/Jh/zeta` token。
- doublet/projector 相关的 runtime 输出不额外添加 projector 路径 token；
  system、hopping、denominator 和 `kramer_file` 身份记录在
  `<output_run>/source.txt` 以及工件 key/metadata 中。
- 路径 token 的数值序列化使用 8 位定点小数。
- Key/hash 序列化仍使用 12 位定点小数。

Code form:
```text
fmt8(x) = format(x, ".8f")
fmt12(x) = format(x, ".12f")  # key/hash only
r42 = F4 / F2
r62 = F6 / F2
core_dir = n-{n}_r42-{fmt8(r42)}_r62-{fmt8(r62)}_scheme-{scheme}
run_dir = (paths.output_run or output_root) / run_name
```

Validation:
- token 集合或数值格式不一致视为 key/path 不匹配。

## 4) 必需文件名契约（MUST）
MUST:
- `core/L0` 锚点必须包含：
  - `f_create_{n}_to_{n+1}.npz`, `f_create_{n-1}_to_{n}.npz`
  - FOPT 额外使用 `p_create_4_to_5.npz`, `p_create_5_to_6.npz`
  - `meta.json`
- `LMSM` 与 `LSJM` 必须包含：
  - `{LEVEL}.npz`, `source.txt`, `meta.json`
- `<output_run>/ligand/{soc,nsoc}/n-{N}` 必须包含：
  - `data.npz`, `source.txt`, `meta.json`
- `IONED/n-{N}` 必须包含：
  - `states.npz`, `meta.json`
- `L1/L2/L3` 必须包含：
  - `data.npz`, `meta.json`
- 带 `runtime.run_name` 的运行会写入：
  - `<output_run>/run.log`
- FOPT L3 额外写入：
  - `exchange.txt`，作为 total/process exchange 的人类可读 sidecar。
- 当 `J_mu` 可用时，SOPT L3 也额外写入 `exchange.txt`。
- FOPT L2 每个 pair 存一个文件：
  - `V_plus_f1_lig1.npz`, `V_plus_f1_lig2.npz`,
    `V_plus_f2_lig1.npz`, `V_plus_f2_lig2.npz`, `meta.json`
- `spin12`（模块 04-03，可选阶段）使用：
  - `data.npz`, `meta.json`

Code form:
```text
required_files_runtime = {data.npz, meta.json}
required_files_LMSM_LSJM = {{LEVEL}.npz, source.txt, meta.json}
```

Validation:
- 缺失必需文件名会阻止缓存复用。

## 5) 载荷语义映射（MUST）
MUST:
- `core/L0/f_create_{n}_to_{n+1}.npz` -> f-shell creation primitive。
- `core/L0/p_create_{N}_to_{N+1}.npz` -> p-shell creation primitive。
- `LMSM/LMSM.npz` -> 模块 03-00 LSMS states 和 energy coefficients。
- `LSJM/LSJM.npz` -> 模块 03-01 LSJM states 和 energy coefficients。
- `IONED/states.npz` -> 模块 03-05 full single-ion ED eigenstates 和
  absolute intermediate-sector energies。
- `L1/data.npz` -> $A^{\kappa,n}_{u j}, B^{\kappa,n-1}_{j v}$。
- `L2/data.npz` -> route factors
  $M_A$, $M_B$
  （或等价分块/因子化表示，并带可精确重构的 metadata）。
- SOPT `L3/data.npz` -> $h_{\mu,abcd},\mathrm{Heff}_{abcd}^{(\mu)}$，并且
  当 projected local space 为二维时，可选包含 `J_mu` 和 `mapping_residual`。
- FOPT `L3/data.npz` -> total `h_eff_4`、按 process 顺序
  `[P1,P2,P3,P4,P5]` 堆叠的 process-resolved `h_eff_4`、以及
  total/process `J_mu` 和 mapping residuals。Runtime FOPT exchange 输出
  要求 projected local space 为二维。
- FOPT `L3/exchange.txt` -> 人类可读的 total 和 process-resolved `J_mu`
  行；`data.npz` 仍是机器契约。
- SOPT `L3/exchange.txt` -> 当 `J_mu` 可用时的人类可读 total `J_mu` 行；
  `data.npz` 仍是机器契约。
- `spin12/data.npz` 保留给可选独立后处理，当前 runtime 不要求它。

Code form:
```text
artifact -> tensor_semantics mapping is mandatory metadata truth
```

Validation:
- `meta.json` 中的 tensor 语义必须与本节一致。

## 6) 能量分项重构契约（MUST）
MUST:
- LMSM 重构：
  `E_lmsm = F0*coef_F0 + F2*coef_F2 + F4*coef_F4 + F6*coef_F6`
- LSJM 重构：
  `E_lsjm = F0*coef_F0 + F2*coef_F2 + F4*coef_F4 + F6*coef_F6 + zeta*coef_zeta`

Code form:
```text
E_lmsm(a) = sum_k Fk * coef_Fk[a]
E_lsjm(a) = E_lmsm(a) + zeta * coef_zeta[a]
```

Validation:
- 重构能量必须在运行时阈值内匹配存储的 energy views。

## 7) 元数据契约（MUST）
MUST:
- `meta.json` 必填字段：
  `schema_version`, `module`, `level`, `key`, `inputs_summary`, `tensor_name`,
  `physical_meaning`, `basis_id`, `index_definition`, `unit`,
  `storage_layout`, `dtype`, `logical_shape`, `payload_files`, `created_at`。
- Runtime 工件如果未经单位转换直接消费 run-input 数值，必须使用
  `unit = "raw"`，除非模块显式写入更具体的 unit。
- 稀疏格式必须包含 `nnz`。
- 因子分解格式必须包含精确重构公式。

Code form:
```text
meta_required = {schema_version,module,level,key,inputs_summary,tensor_name,
                 physical_meaning,basis_id,index_definition,unit,
                 storage_layout,dtype,logical_shape,payload_files,created_at}
```

Validation:
- 缺失必需 metadata 是硬契约错误。

## 8) Key 契约（MUST）
MUST:
- 工件身份有两种机制。共享的 **core** 层是 content-addressed，可跨运行复用；
  **run-scoped** 层仅由 `runtime.run_name` 识别。

- Core 层（content-addressed，跨运行共享）：
  - `LMSM`: `{n, r42, r62, standard_version}`，其中 `r42/r62` 由输入
    `F2/F4/F6` 派生。
  - `LSJM`: `{keyLMSM, standard_version}`。
  - `L0`: `{n, standard_version}`。

- Run-scoped 层（identity = `run_name`）：
  - `IONED`、`L1`（所有 scheme 和 Kramers route）、`L2`、SOPT/FOPT `L3`
    以及 `spin12` 都仅由 `runtime.run_name` keyed，并位于解析后的 run
    anchor 下。`L1/F` 是 run-scoped，正是这一点允许相邻扇区使用自己的
    Slater ratio 而无需 branch token。
  - 这些 identity 不包含参数 token、content digest 或嵌入式 parent key。
    复用由 run path 下的工件是否存在决定（见 §9），而不是由 key equality 决定。
  - 保持同一个 `run_name` 却改变任何 run input，会复用已有 run-scoped 工件；
    需要重算时必须换新 `run_name` 或删除 run directory。

- Provenance 而非 identity：`hopping_name`、输入文件路径、解析后的
  denominator/ligand 参数会记录在 `<output_run>/source.txt` 以及工件
  `meta.json`/index record 中，用于搜索和审计，但不属于 run-scoped
  artifact identity。

Code form:
```text
key(core level)       = deterministic content tuple
key(run-scoped level) = run_name
```

Validation:
- Core key 不匹配会使缓存不兼容。
- Run-scoped 复用由 run path 下的工件是否存在决定（见 §9）。

## 9) 先读后算策略（MUST）
MUST:
- 对每个目标工件：
  1) 按 key/token 计算路径；
  2) 若存在则校验并读取；
  3) 若缺失或无效则计算并原子写入。
- 运行窗口必须是连续区间：
  `start_level ... end_level`，并满足
  `start_level,end_level in {LMSM,LSJM,L0,L1,L2,L3}`
  且 `start_level <= end_level`。
- 从 `start_level` 启动前，实现必须 preflight-check 所需上游工件和窗口必需输入字段。
- 预扫描上游依赖映射：
  - `LMSM` 依赖 `{}`
  - `LSJM` 依赖 `{LMSM}`
  - `L0` 依赖 `{}`
  - `L1` 依赖 `{LMSM, LSJM, L0}`
  - `L2` 依赖 `{L1}` 加 hopping 输入和 projector `W`
  - `L3` 依赖 `{L2}` 加 SOPT denominator 输入；
    FOPT `L3` 依赖 `{L2}` 加 ligand/f-sector energies
- 预扫描阶段发现所需上游工件缺失或无效时，必须硬失败。
- 高于 `end_level` 的层级不得执行，也不得写入工件。
- 仅预计算运行用 `end_level <= L2` 表示。

Code form:
```text
if exists(target) and validate(target):
  load(target)
else:
  compute()
  atomic_write(target)

for level in [LMSM,LSJM,L0,L1,L2,L3]:
  if level > end_level:
    skip(level)
```

Validation:
- 未校验直接重写属于契约违规。
- 预扫描违规使用 `FXE-IO-001/002`。

## 10) 外部输入边界（MUST）
MUST:
- `hopping` 和统一的 `kramer_file` 计算输入都是外部运行时输入。
- `./outputs/.../input_hopping.npz` 和
  `./outputs/.../input_kramer.npz` 只是审计快照，不是计算源。
- 外部输入缺失必须失败（禁止回退到快照）。

Code form:
```text
source_hopping = external_input_only
source_kramer  = external_input_only
```

Validation:
- 任何 fallback-to-snapshot 行为都是硬失败。

## 10.1) 阶段局部 Exchange 文本导出（MUST）
人类可读的 exchange 文本输出是 stage-local：
- 当 `J_mu` 可用时，SOPT 在 `L3` 工件目录下写 `exchange.txt`。
- FOPT 在 `L3` 工件目录下写 `exchange.txt`。
- 实现不得额外在 `output_root` 直属位置写 shallow point-result 文本文件。

## 10.2) Run Log 导出（MUST）
带 `runtime.run_name` 的运行必须在 run-level 写日志：

```text
<output_run>/run.log
```

即便 console output 被较高 `--log-level` 过滤，文件日志也必须包含 stage summaries。

## 11) 全局索引契约（MUST）
MUST:
- 维护追加式 `./outputs/index.jsonl`。
- 每行至少包含：
  `key,module,level,path,created_at,n,r42,r62,U,Jh,zeta,hopping_name,kramer_file,content_hash`（按适用项）。

Code form:
```text
append(index.jsonl, index_record)
```

Validation:
- 缺失必需索引字段会破坏可追溯契约。

## 12) 边界与优先级（MUST）
MUST:
- 本文件是规范性 I/O 契约。
- 非规范目录样例与可选工程策略见
  `./standards/en/05-io/05-01-IO_LAYOUT.md`。
- 若出现冲突，以本文件为准。

## 13) 并行落盘规则（MUST）
MUST:
- 工件持久化必须保持单写者规则。
- 当前参考实现以串行为主；若未来 runtime 计算 local shards，也必须由一个指定写入者
  组装完整 tensor/matrix 后再持久化。
- `04-03`（spin12）层按默认契约仍为串行。
- 非写入者不得写阶段 `data.npz`/`meta.json`。
- 写入 `meta.json` 的 runtime metadata 必须与实际使用的 backend 一致。

Code form:
```text
local = compute(...)
full  = assemble_for_single_writer(local)
if writer_role:
  write(full, meta)
else:
  no_persist_write()
```

Validation:
- 同一路径工件禁止并发写入。
