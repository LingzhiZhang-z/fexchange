# 05-00-IO

本文件定义跨模块工件的**规范性**磁盘 I/O 契约。
本文件全部规则均为 MUST 级约束。
非规范性的目录样例与可选工程策略移到 `./standards/en/05-io/05-01-IO_LAYOUT_GUIDE.md`。

## 1) 适用范围（MUST）
MUST:
- 本文件只定义磁盘 I/O 契约。
- 物理语义由 `03-00/03-01/04-00/04-01/04-02/04-03` 定义。
- 运行时数值与输入闸门继承
  `./standards/en/00-conventions/00-02-RUNTIME_NUMERICS_AND_INPUT_GATES.md`。

Code form:
```text
io_contract_scope = {paths, filenames, metadata, key, read-first policy}
```

Validation:
- 任何违反本文件的工件都不得被下游复用。

## 2) 根目录与阶段锚点（MUST）
MUST:
- 所有持久化工件必须位于 `./outputs/`。
- 运行输入字段 `paths.output_root` 为必填，且在本标准版本中必须严格为
  `./outputs`（不允许替代输出根目录）。
- `L0` 磁盘锚点为 `./outputs/fock/`。
- `LMSM/LSJM/L1/L2/L3/L4/spin12` 磁盘锚点在 `./outputs/core/...`。

Code form:
```text
root_outputs = ./outputs
anchor_L0    = ./outputs/fock
anchor_core  = ./outputs/core
```

Validation:
- 任何落盘到 `./outputs/` 之外的阶段输出都属于契约失败。

## 3) 路径参数契约（MUST）
MUST:
- core 路径必须包含：
  `n-{n}_r42-{r42}_r62-{r62}_scheme-{scheme}`。
- 路径/key 中的 `r42/r62` 是运行输入派生值：
  `r42 = F4/F2`、`r62 = F6/F2`（要求 `F2 != 0`）。
- L2/L3/L4 的路径层次必须将 `hopping` 放在 `U/Jh/zeta` 之上：
  `.../hopping/{hopping_name}/U-{U}_Jh-{Jh}_z-{zeta}/...`。
- L2 路径必须包含 `hopping/{hopping_name}`，且不要求
  `U/Jh/zeta` token。
- L3/L4 路径必须同时包含 `hopping/{hopping_name}` 与
  `U-{U}_Jh-{Jh}_z-{zeta}`。
- L4 路径还必须包含 `kramer/{kramer_name}`。
- `r42/r62/U/Jh/z` 统一使用 12 位定点小数序列化。

Code form:
```text
fmt12(x) = format(x, ".12f")
r42 = F4 / F2
r62 = F6 / F2
core_dir = n-{n}_r42-{fmt12(r42)}_r62-{fmt12(r62)}_scheme-{scheme}
hopping_dir = hopping/{hopping_name}
u_jh_z_dir  = U-{fmt12(U)}_Jh-{fmt12(Jh)}_z-{fmt12(zeta)}
```

Validation:
- 路径 token 缺失或格式不一致视为 key/path 不匹配。

## 4) 必需文件名契约（MUST）
MUST:
- `fock` 锚点必须包含：
  - `n{n}{n+1}.npz`, `n{n-1}{n}.npz`
  - `meta_n{n-1}.json`, `meta_n{n}.json`, `meta_n{n+1}.json`
- `LMSM` 与 `LSJM` 必须包含：
  - `V.npz`, `E_terms.npz`, `meta.json`
- `L1/L2/L3/L4` 必须包含：
  - `data.npz`, `meta.json`
- `spin12`（模块 04-03，可选阶段）必须包含：
  - `data.npz`, `meta.json`

Code form:
```text
required_files_L1_L4 = {data.npz, meta.json}
required_files_LMSM_LSJM = {V.npz, E_terms.npz, meta.json}
```

Validation:
- 缺失必需文件名时，不得复用缓存。

## 5) 载荷语义映射（MUST）
MUST:
- `fock/n{n}{n+1}.npz` -> $X^{\kappa,n}_{\alpha\beta}$。
- `fock/n{n-1}{n}.npz` -> $Y^{\kappa,n-1}_{\beta\gamma}$。
- `LMSM/V.npz` -> 模块 03-00 LSMS 态。
- `LMSM/E_terms.npz` -> `coef_F0/F2/F4/F6`。
- `LSJM/V.npz` -> 模块 03-01 LSJM 态。
- `LSJM/E_terms.npz` -> `coef_F0/F2/F4/F6/coef_zeta`。
- `L1/data.npz` -> $A^{\kappa,n}_{u j}, B^{\kappa,n-1}_{j v}$。
- `L2/data.npz` -> 路线因子
  $M_A$, $M_B$
  （或等价分块/因子化表示，并带可精确重构的 metadata）。
- `L3/data.npz` -> $h_{\mathrm{pre},j_3 j_4,j_1 j_2}^{(\mu)}$。
- `L4/data.npz` -> $h_{\mu,abcd},\mathrm{Heff}_{abcd}^{(\mu)}$。
- `spin12/data.npz` -> `J_mu` 及派生量（`J_iso/K/D/Gamma/const/h_i/h_j/residual`）。

Code form:
```text
artifact -> tensor_semantics mapping is mandatory metadata truth
```

Validation:
- `meta.json` 中语义必须与本节一致。

## 6) 能量分项重构契约（MUST）
MUST:
- LMSM 重构：
  `E_lmsm = F0*coef_F0 + F2*coef_F2 + F4*coef_F4 + F6*coef_F6`
- LSJM 重构：
  `E_lsjm = F0*coef_F0 + F2*coef_F2 + F4*coef_F4 + F6*coef_F6 + zeta*coef_zeta`

Code form:
```text
E_lmsm(a) = sum_k Fk * coef_Fk[a]
E_lsjm(a) = E_lmsm(a) + zeta * coef_zeta[a]
```

Validation:
- 重构能量与存储能量视图必须在运行时阈值内一致。

## 7) 元数据契约（MUST）
MUST:
- `meta.json` 必填字段：
  `schema_version`, `module`, `level`, `key`, `inputs_summary`, `tensor_name`,
  `physical_meaning`, `basis_id`, `index_definition`, `unit`,
  `storage_layout`, `dtype`, `logical_shape`, `payload_files`, `created_at`。
- 稀疏格式必须包含 `nnz`。
- 因子分解格式必须包含精确重构公式。

Code form:
```text
meta_required = {schema_version,module,level,key,inputs_summary,tensor_name,
                 physical_meaning,basis_id,index_definition,unit,
                 storage_layout,dtype,logical_shape,payload_files,created_at}
```

Validation:
- 缺字段属于硬契约错误。

## 8) Key 契约（MUST）
MUST:
- `LMSM`: `{n, r42, r62, standard_version}`，其中 `r42/r62` 由输入 `F2/F4/F6` 派生。
- `LSJM`: `{keyLMSM, standard_version}`
- `L0`: `{n, standard_version}`
- `L1`: `{keyLSJM, fn_ground_subspace_id, standard_version}`
- `L2`: `{keyL1, hopping_name, standard_version}`
- `L3`: `{keyL2, U, Jh, zeta, standard_version}`
- `L4`: `{keyL3, kramer_name, standard_version}`
- `spin12`: `{keyL4, kramer_basis_id, standard_version}`
- `hopping_name` 与 `kramer_name` 必须来自
  `run_input.toml` 的 `[sources].hopping_name` / `[sources].kramer_name`，
  且在同一项目缓存命名空间中保持稳定不可变。

Code form:
```text
key(level) = deterministic tuple per level contract
```

Validation:
- key 不匹配时缓存不可兼容。

## 9) 先读后算策略（MUST）
MUST:
- 对每个目标工件：
  1) 按 key/token 定位路径；
  2) 若存在则校验并读取；
  3) 若缺失或校验失败则计算并原子写入。
- 运行窗口必须是连续区间：
  `start_level ... end_level`，并满足
  `start_level,end_level in {LMSM,LSJM,L0,L1,L2,L3,L4}`
  且 `start_level <= end_level`。
- 从 `start_level` 启动前，必须先预扫描并校验所需上游工件与窗口必需输入字段。
- 预扫描上游依赖映射：
  - `LMSM` 依赖 `{}`
  - `LSJM` 依赖 `{LMSM}`
  - `L0` 依赖 `{}`
  - `L1` 依赖 `{LMSM, LSJM, L0}`
  - `L2` 依赖 `{L1}`
  - `L3` 依赖 `{L2}`
  - `L4` 依赖 `{L3}`
- 预扫描阶段发现上游缺失或无效时，必须硬失败。
- 高于 `end_level` 的层级禁止执行，也禁止写入对应工件。
- 仅预计算可用 `end_level <= L2` 表达。

Code form:
```text
if exists(target) and validate(target):
  load(target)
else:
  compute()
  atomic_write(target)

for level in [LMSM,LSJM,L0,L1,L2,L3,L4]:
  if level > end_level:
    skip(level)
```

Validation:
- 未校验直接重写属于契约违规。
- 预扫描违规使用 `FXE-IO-001/002`。

## 10) 外部输入边界（MUST）
MUST:
- `hopping` 与 `kramer` 的计算源输入必须来自外部运行时输入。
- `./outputs/.../input_hopping.npz` 与
  `./outputs/.../input_kramer.npz` 仅作审计快照，不可作计算源。
- 外部输入缺失必须失败（禁止回退到快照）。

Code form:
```text
source_hopping = external_input_only
source_kramer  = external_input_only
```

Validation:
- 任何“回退到快照继续算”的行为都是硬失败。

## 11) 全局索引契约（MUST）
MUST:
- 维护追加式 `./outputs/index.jsonl`。
- 每行至少包含：
  `key,module,level,path,created_at,n,r42,r62,U,Jh,zeta,hopping_name,kramer_name,content_hash`（按适用项）。

Code form:
```text
append(index.jsonl, index_record)
```

Validation:
- 缺失必需索引字段会破坏可追溯契约。

## 12) 边界与优先级（MUST）
MUST:

- 非规范目录样例与可选工程策略见
  `./standards/en/05-io/05-01-IO_LAYOUT_GUIDE.md`。

## 13) 并行落盘规则（MUST）
MUST:
- 详细 MPI/并行运行时约束继承
  `./standards/en/00-conventions/00-06-MPI_PARALLEL_RUNTIME.md`。
- 并行/MPI 可以在 worker rank 上计算分片。
- 例外：`04-03`（spin12）层按默认契约仅允许 root 串行执行。
- 持久化写入必须单写者：由 root rank 组装完整矩阵/张量后写入。
- 非 root rank 禁止写阶段 `data.npz`/`meta.json`。
- 运行并行摘要必须输出到 stdout，且写入 `meta.json`
  （至少包含 `parallel_backend`, `world_size`, `root_rank`, `local_rank`, `gather_policy`）。

Code form:
```text
local = compute_local_shard(...)
full  = gather_to_root(local)
if rank == root:
  write(full, meta)
else:
  no_persist_write()
```

Validation:
- 多 rank 并发写同一路径工件属于禁止行为。
